config plan

file storage:
- configs folder: JSONs for each saved config
- persistent state JSON: activeConfig (null or file name), could also have using mock data and other settings
React:
- current config in store
- list of configs as component state in ConfigDisplay 
Rust:
- current config in app state 

first init:
- create configs folder
- create persistent state JSON with activeConfig null
- UI should handle null
  - live - says no robot/config
  - graph - says no robot/config
  - config - says no current config and no configs available

select config
- React updates state JSON with activeConfig 
- React updates its store
- React tells Rust current config was updated
- Rust checks state JSON for config, fetches it, and updates its app state 

create new config (also saves as current config)
- React updates state JSON with activeConfig 
- React updates its store
- React ConfigDisplay updates its list
- React tells Rust current config was updated
- Rust checks state JSON for config, fetches it, and updates its app state to null

edit current config
- React saves config JSON 
- React updates its store
- React tells Rust current config was updated
- Rust checks state JSON for config, fetches it, and updates its app state 


delete current config
- React deletes config JSON
- React updates state JSON with activeConfig null
- React updates its store
- UI should handle null 
- React tells Rust current config was updated
- Rust checks state JSON for config, fetches it, and updates its app state to null
